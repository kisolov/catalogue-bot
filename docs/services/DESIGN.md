# Решения

Обоснования сквозных решений. Решения отдельных доменов —
в их `DESIGN.md` ([orders](orders/DESIGN.md), [auth](auth/DESIGN.md)).

## Вход только через Telegram, `POST /users/` — только админ

- **Решение:** публичной регистрации нет; пользователь создаётся при первом входе через подписанный `initData`.
- **Альтернативы:** оставить открытый `POST /users/`.
- **Почему так:** открытый endpoint с полем `role` позволял любому выдать себе `admin`.

## Миграции при старте с учётом применённых

- **Решение:** таблица `schema_migrations`, каждый файл выполняется один раз.
- **Альтернативы:** `initdb.d` Postgres; Alembic.
- **Почему так:** перезапуск контейнера падал с `DuplicateObject`. `initdb.d` не переживает существующий volume; Alembic избыточен для двух файлов, но переход на него возможен позже. Изменения схемы идут новым файлом `db_00N_…`: уже применённый `db.sql` правкой не изменить.

## Авторизация — зависимости во входном слое, отказы — доменные исключения

- **Решение:** `get_current_user`/`get_current_admin` лежат в [`bootstrap/dependencies`](../../src/bootstrap/dependencies/auth.py); токен разрешает use case `AuthenticateByToken`; отказы — `NotAuthenticated`/`PermissionDenied`/`TokenException`, в HTTP их превращает `server_factory`.
- **Альтернативы:** оставить `HTTPException` в доменном пакете `auth`.
- **Почему так:** домен не должен знать про HTTP; маппинг статусов остаётся в одном месте.

## Оплата вне объёма

Заказ создаётся в статусе `new`, платёжный шлюз — отдельный этап.

## Асинхронный доступ к БД: SQLAlchemy 2.0 + asyncpg

- **Решение:** порты, сервисы и use case — `async`; адаптеры — SQLAlchemy 2.0 (`AsyncSession`, драйвер `asyncpg`) без `relationship`; одна транзакция на операцию адаптера ([`Database.transaction`](../../src/shared/db.py)); Redis — `redis.asyncio`. Тесты идут через `httpx.AsyncClient` на одном event loop.
- **Альтернативы:** оставить Pony ORM (синхронный: каждый запрос к БД блокировал бы event loop, обход — `asyncio.to_thread` в use case); SQLAlchemy в синхронном режиме.
- **Почему так:** эндпоинты уже были `async def`, но синхронный драйвер останавливал весь процесс на время SQL-запроса. `to_thread` оставил бы синхронный драйвер и ограничил параллелизм пулом потоков. Цена перехода: во всех слоях `await`, а связанные данные адаптер запрашивает явно (ленивой подгрузки в async нет), поэтому `relationship` не используются, а дерево категорий читается по уровням.

## Один монолит и одна БД

Домены небольшие и связаны транзакцией (заказ ↔ корзина ↔ остатки). Разнос по сервисам потребовал бы саг и outbox без выигрыша на таком объёме.

## Защита периметра

**Решение.** Секреты не попадают в логи (маскирование в `LoggingMiddleware`), CORS без `*` и без credentials, `forwarded_allow_ips` — подсеть compose, а не `*`; Redis с паролем; Swagger выключен по умолчанию; лимиты запросов и заголовки безопасности — в nginx.

**Альтернативы.** Лимиты в приложении (slowapi + Redis); маскирование через фильтр логгера; хранение JWT в cookie.

**Почему так.** Лимиты в nginx срабатывают до Python и не требуют новой зависимости; маскирование в middleware закрывает источник утечки, а не следствие; токен в заголовке `Authorization` исключает CSRF, поэтому credentials в CORS не нужны. TLS терминируется выше nginx и в проект не входит.
