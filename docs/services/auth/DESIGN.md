# auth — решения

## JWT + хранение в Redis, а не «чистый» JWT

- **Решение:** токен проверяется по подписи и по наличию в Redis.
- **Альтернативы:** stateless JWT без хранилища; серверные сессии в БД.
- **Почему так:** нужен немедленный отзыв (`logout`), а Redis уже есть в стеке и умеет TTL. Цена: отказ Redis = отказ авторизации.

## Проверка `initData` — чистая логика без порта

- **Решение:** `TelegramInitDataService` — обычный класс без интерфейса.
- **Альтернативы:** `TelegramValidator` как порт с адаптером.
- **Почему так:** зависимостей от внешнего мира нет (только токен бота из настроек), подмена не нужна; порт был бы церемонией.

## Без refresh-токенов

- **Решение:** живёт один access-токен 24 ч.
- **Альтернативы:** пара access/refresh.
- **Почему так:** Mini App каждый раз получает свежий `initData` от Telegram, повторный вход бесшовный.
